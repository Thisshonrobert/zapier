## Deliberate narrowings and deviations

- **No API, contract or policy change.** The operator case projection still carries no Zap name or step label, so an operator index row shows the failure summary instead, and the step handler appears in the case file only once the captured failure evidence loads. The evidence room reads the existing operator and engineering endpoints; nothing new was added to the backend.
- **Two new presentation dependencies on existing data only.** `providerOutcomeShort` exists because the full "Provider accepted the request (delivery is not confirmed)" sentence displaced the identity line in a case header; the long form is still used everywhere the fact is the subject of the sentence.
- **Engineering has no input-validation tab.** There is no validation route under `/engineering`, so that tab reports `input_validation_not_authorized_here` rather than calling an operator-only endpoint or hiding the tab.
- **The evidence room reads on a case selection, not on an investigation.** Deterministic failure facts exist before any model call, so the room is useful with no investigation and no paid call.
- **`TriageResults.tsx` and `CommandCenter.tsx` are deleted rather than kept as unused shims.** Their tests were rewritten against the new components, so no empty dead file remains.

## Known limits recorded at planning time

- The Next.js dev server cannot start under the file sandbox (`spawn EPERM`, the boundary recorded for `frontend#build` since 16C), so the visual inspection ran against a harness that renders the real components with the compiled Tailwind stylesheet, and the interactive verification ran against the same components mounted in a browser.
- The `useTriage`/`useCommandCenter`/`triage-stream` `AbortSignal.any` type errors and the `ReplayOperatorAction` name mismatch pre-date this phase and are unchanged.
