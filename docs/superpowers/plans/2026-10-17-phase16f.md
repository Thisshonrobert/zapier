## Deliberate narrowings and deviations

- **Eligibility rides the investigation snapshot.** The spec asks for a capability/eligibility summary as evidence before an advisory exists; the authority snapshot already runs the same deterministic policy, so the summary is projected there rather than duplicated onto a new agent evidence contract that the agent cannot compute.
- **The model keeps its advisory proposal.** An ungrounded `replay_candidate` is stored as the model wrote it and the durable proposal status stays policy-computed (`blocked`). Eligibility is never rewritten from the model, and no automatic approval is introduced.
- **The dry run is the operator's review step, not a stored permit.** The client requires a fresh dry run after approval before it will submit a request, and the request path revalidates the same frozen evidence and current facts immediately before it commits. No dry-run permit row is persisted, so a manually constructed request cannot skip the review, but it also gains nothing: the request revalidates.
- **History reads metadata only.** The case-wide history returns request identity, which proposal authorized it, publication/execution state and the recorded provider outcome. It never returns the stored original execution snapshot.
- **`REPLAY_RELEASE_READY` stays false in code.** The lab override is a separate verified profile value, not a relaxation of the production constant.
- **The lab replay journey uses a fixed bounded F01 advisory.** The lab runs no paid model, so the advisory diagnosis is the documented contract shape assembled from the case's live evidence. Eligibility, approval, request, publication and execution run the real application code path.
