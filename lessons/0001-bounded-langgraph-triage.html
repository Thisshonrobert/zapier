Make uncertainty a first-class result

The first agent is useful because it can stop safely. Its job is to turn observed facts into a cited proposal, while deterministic code rejects unsupported replay advice.

The production shape

Express owns transport and server lifetime. Zod rejects malformed HTTP input, fixture data, and model output. LangGraph.js makes the two state transitions explicit. The injected model interface keeps provider choice outside the graph.

F01: explicit 429 rejection. Every attempt was rejected and a retry window was returned. A proposal may say “wait, obtain approval, then request replay.” The agent still performs no replay.
F07: timeout with unknown delivery. The client did not receive a response. The provider may still have accepted the request. The safe result is insufficient_evidence and reconciliation before replay.

Retrieval check

Without looking at the answer, explain this in one or two sentences: A Telegram send times out before a response arrives. What may the agent conclude, and why?

Reveal the target reasoning

It may conclude only that delivery is unknown. A timeout describes what the caller observed, not what Telegram did, so replay must wait for a receipt or another deterministic reconciliation signal.

Read the implementation as a system

  1. Start at http.ts and find the server lifecycle boundary.
  2. Follow the request into graph.ts. Identify the two nodes and the tool, step, and time budgets.
  3. In contracts.ts, find the three separate untrusted inputs.
  4. Run the F01 and F07 tests and explain why the expected proposals differ.
